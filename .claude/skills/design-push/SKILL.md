# /design-push — codebase → claude.ai/design

Push the CURRENT design (tokens + UI primitives + compositions) to the claude.ai/design design-system project so the owner can edit it visually there. Counterpart: `/design-pull`.

## Steps

1. **Regenerate the bundle** (always — never push a stale dist):
   ```bash
   node scripts/design-sync/build-bundle.mjs
   ```
   Output: `scripts/design-sync/dist/` (gitignored). If extraction fails (regex misses after a shadcn component was restructured), fix `build-bundle.mjs` extraction first — never hand-edit dist.

1b. **Screens (optional but recommended when UI changed):** live per-resolution snapshots of the real app. Requires auth for authenticated screens — NEVER put the password literally in a command you run. Two ways:
   ```bash
   # preferred (no password handling): reuse a saved Playwright storage state
   DESIGN_SNAPSHOT_STORAGE_STATE=.codex/worktrees/QA-GATE/output/playwright/qa-user-sim/storage-state.json \
     node scripts/design-sync/snapshot-screens.mjs
   # or the USER runs it themselves (via `!` prefix) with their creds:
   E2E_XUI_USERNAME=... E2E_XUI_PASSWORD=... node scripts/design-sync/snapshot-screens.mjs
   ```
   Without either it captures only the Login screen. The script auto-starts the dev server if needed and merges `screens/*` into `bundle.json`. `build-bundle.mjs` preserves existing `dist/screens/` — stale screens are better than none, but tell the user when screens predate the UI change.

2. **Find the project** with `DesignSync list_projects`. Target project name: **"Lumen Player Design System"**. If missing, `create_project` with that name. Verify with `get_project` that it is `PROJECT_TYPE_DESIGN_SYSTEM` before any write.

3. **Diff remote**: `list_files` on the project. New/changed/removed files vs local dist (compare against `bundle.json` card hashes only structurally — do NOT `get_file` everything).
   - **STOP AND WARN** if remote files differ from what the last push wrote and the user has NOT yet pulled: pushing would overwrite their claude.ai/design edits. Offer `/design-pull` first. Only proceed on explicit confirmation.

4. **Plan + write**:
   - `finalize_plan` with `localDir: scripts/design-sync/dist`, `writes: ["**/*"]`, and `deletes` for remote paths no longer in the bundle.
   - `write_files` using `localPath` for every file (contents must not enter context).
   - `@dsCard` markers cover files present when the app builds its index (`_ds_manifest.json`). **For paths ADDED in a later push the index is stale and `register_assets` does NOT reach this pane** (verified 2026-07-07: registered assets never appeared in `_ds_manifest.json`). Instead: `get_file _ds_manifest.json`; if any pushed path is missing from `cards[]`, rewrite the manifest — preserve everything, append the missing `{path, group, name}` entries to `cards[]` — and push it via a plan that includes `_ds_manifest.json`. The `tokens` array can be regenerated by parsing `foundations/tokens.css` blocks (`:root` unscoped, `.dark`/`.light` scoped; kind: `radius` for --radius, `color` for --surface-*/--shell-border, `shadow` for --shell-shadow, else `other`).

5. **Report**: list pushed cards (group/name), the project name, and remind the user: edits made there come back with `/design-pull`.

## Rules

- The bundle is DERIVED — the source of truth for design is the codebase (`apps/web/src/index.css`, `components/ui/*`). Push never modifies the codebase.
- `foundations/tokens.css` must always be the verbatim token block copy; it is the mechanical round-trip file.
- Never push partial bundles; always regenerate + push the full set so hashes in `bundle.json` stay truthful.
